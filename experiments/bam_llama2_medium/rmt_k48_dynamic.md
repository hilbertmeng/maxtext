- Implementation: `/data0/xd/rmt-k48-dynamic`, branch `codex/rmt-k48-dynamic`, corrected runtime `70422c09540e32fe6e4d22c8433295ecec052ad5`.
- RUNs: `RMTMediumPropAlibiK48DynamicTail32` on `xd-v5p-16-9-maxtext` (launched 2026-09-25 07:49 UTC) and `RMTMediumPropAlibiK48DynamicFull48` on `xd-v5p-16-10-maxtext` (launched 07:55 UTC); both `v5p-16` with `us-east5-a` primary and `europe-west4-b` backup.
- Direct loss controls: static `RMTMediumPropAlibiK48`, dynamic BAM `BamMediumPropK75AllLocalMOnlyAlibiRMTBudget`, and ALiBi MHA `BamMHAMediumPropAlibiC256`.
- Both RUNs retain RMT static attention and MLP reads/writes. Extra Q/K use full-M shared rank4; V/O share a C8 read with independent gates; MLP has its own C8 read. Attention and MLP have separate GELU-R256 write-address projections. Tail32 writes only matrix rows 16–47 dynamically; Full48 writes all rows dynamically. Static RMT writes still cover all 48 rows in both arms.

## Full48 without dynamic O read

- `RMTMediumPropAlibiK48DynamicFull48NoO` uses the same Full48 architecture, schedule, health capture and MLP width2711, but drops the extra BAM-style dynamic O read. Native RMT attention-output writing remains. V retains the shared C8 key/read; only the O gate and injection are removed.
- Runtime: same worktree/branch, commit `c2dcd600aa0f0f8d864f3277d33c6c18a757e035`; 328,238,064 parameters, 345,888 fewer than Full48 (0.105%), without an MLP adjustment. Direct comparisons: Full48, static RMT K48, ALiBi MHA.
- Pre-run bet for final five 200-step points: NoO−Full48 `+0.015`, NoO−static RMT K48 about `−0.055`; speed about 1% faster than Full48. Full48 and NoO health schemas are identical, with NoO O-route metrics zero.
- Validation: seven RMT unit tests passed; exact full-model parameter-tree audit and sealed runtime config passed. The new flag explicitly preserves O on Full48; this matters because the config object returns `None` for a missing attribute.
- Formal AOT `c2dcd60-39f6e56d.json` compiled on the retained `llm-jax-v6e-1-1` FLEX_START v6e-1 without lifecycle transfer. RUN started on `xd-v5p-16-11-maxtext` in UE5a after an UE5a-only queue, launched 2026-09-25 08:56 UTC. `Loaded compiled function!` and `FIRST_STEP` were verified.
